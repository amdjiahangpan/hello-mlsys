## 本章导读

> 本章建立通信的一阶代价模型 T ≈ α + β × Data，并区分“行为验证”与“性能验证”。读完后，你应该能判断一次集合通信处在延迟主导区还是带宽主导区。

## 5.1 节点内与节点间互联

比较 PCIe、xGMI 等节点内链路与 InfiniBand、RoCEv2 等节点间网络的带宽与延迟量级。

## 5.2 集合通信原语

理解 All-Reduce、All-Gather、All-to-All 的数据流动方式。

## 5.3 α–β 代价模型

用启动开销与带宽项刻画通信时间。

## 5.4 模拟器实验：不同拓扑下的 All-Reduce

预测不同拓扑下 All-Reduce 时间随数据量的变化，标出延迟主导区与带宽主导区的分界点。

## 5.5 真机实验：主机与设备间带宽

测量 H2D / D2H 带宽，作为 PCIe 路径的实测参考。

## 5.6 行为验证与性能验证

观察集合通信 API 与拓扑感知逻辑的真实行为，明确哪些实测值不能代表多卡性能。
