## 本章导读

> 本章建立通信的一阶代价模型 T ≈ α + β × Data，并区分"行为验证"与"性能验证"。读完后，你应该能判断一次集合通信处在延迟主导区还是带宽主导区。

## 教学目标

- 能说清节点内互联（PCIe、xGMI）与节点间互联（InfiniBand、RoCEv2）的带宽 / 延迟量级差异；
- 能描述 All-Reduce、All-Gather、All-to-All 等集合通信原语的数据流动方式；
- 能用 α–β 模型 T ≈ α + β × Data 预测通信时间，并判断延迟主导区与带宽主导区；
- 能区分"行为验证"与"性能验证"，说明哪些实测值不能代表多卡性能。

## 内容梗概

### 节点内与节点间互联

比较 PCIe、xGMI 等节点内链路与 InfiniBand、RoCEv2 等节点间网络的带宽与延迟量级。

### 集合通信原语

理解 All-Reduce、All-Gather、All-to-All 的数据流动方式。

### α–β 代价模型

用启动开销 α 与带宽项 β 刻画通信时间：T ≈ α + β × Data。

### Scale-in / Scale-up 的具体实现（行为级）

在单卡多进程上观察集合通信 API 与拓扑感知逻辑的真实行为。明确这是行为验证，不是多卡性能验证。

## 实验设计

### 模拟器实验

给定数据量，在"PCIe 单跳""xGMI""100G RoCEv2"三种拓扑下分别预测 All-Reduce 时间，画出通信时间随数据量变化的曲线，标出延迟主导区和带宽主导区的分界点。

### 真机实验（单卡，仅验证行为语义）

单卡无法测真实卡间带宽，但可以做两件事：

- 测 H2D / D2H 带宽（`rocm-bandwidth-test`），作为"PCIe 路径"的实测下限；
- 用单卡多进程 + `gloo` 后端跑一次 All-Reduce，观察通信操作在进程间的真实行为（虽然走的是 CPU / 共享内存路径，但可以让学生看到"集合通信的 API 和拓扑感知逻辑"长什么样）。明确告诉学生：这里的实测值不代表多卡性能，只用于验证"通信原语的行为语义"。

### 闭环与交付

- **预测（测前留存）**：各拓扑的 All-Reduce 时间曲线与两个主导区的分界点。
- **实测（选点运行）**：H2D / D2H 带宽（PCIe 路径下限）；`gloo` 路径的 All-Reduce 行为观察。
- **校准（解释误差）**：α–β 参数与 PCIe 路径实测的对照；多卡卡间带宽的实测待双卡资源（核心真机交付见课程计划的 C04 单机双卡测量）。
- **决策（提交）**：消息大小预测 / 实测曲线、α–β 参数与端到端外推边界（注明实测部分不代表多卡性能）。
