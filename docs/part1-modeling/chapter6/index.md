## 本章导读

> 本章以模拟器为主角，面对一个单卡放不下的模型做真实的切分决策。读完后，你应该能用每卡显存与通信占比两个指标比较不同并行方案。

## 教学目标

- 能说明 DP / FSDP 的显存冗余与梯度同步、TP 的层内切分与频繁通信、PP 的层间切分与流水线气泡；
- 能给出"切分收益被通信吃掉"的判定条件；
- 能用模拟器比较 DP / TP / PP 三种方案的每卡显存占用与通信时间占比；
- 能在真机上观察多 rank 代码路径（行为验证），并把它与性能验证明确分开。

## 内容梗概

### DP / FSDP

理解数据并行的显存冗余与梯度同步。

### TP

理解层内切分与频繁通信；TP 组通常必须限制在同一节点内。

### PP

理解层间切分与流水线气泡。

### 切分收益何时被通信吃掉

给出切分收益与通信代价的判定条件。

## 实验设计

### 模拟器实验（本章模拟器是主角）

- 给定一个"单卡放不下"的模型，让学生用 DP / TP / PP 三种方案各拆一次，模拟器分别输出"每卡显存占用"和"通信时间占比"；
- 设计一个显存刚刚卡在 W7900D 48 GB（规格待确认）或 9070 XT 16 GB 边界的模型配置，迫使学生做出真实的切分决策；
- 留出验证：换一个模型规模，检查"TP 组必须限制在同一节点内"的结论是否依然成立。

### 真机实验（单卡，行为验证）

用 `gloo` 后端在单卡上启动 2–4 个 rank，模拟 TP / DP 的代码路径（PyTorch 的 `torch.distributed` 在 `gloo` 下走 CPU 集合通信，代码路径与真实多卡一致）。可以真实观察到：

- 切分后每个 rank 的模型分片显存占用；
- All-Reduce 的调用次数和顺序；
- 但不能把这里的通信耗时当作 GPU 间通信性能——它只是 CPU 共享内存路径。教学上把"行为验证"和"性能验证"明确分开。

### 闭环与交付

- **预测（测前留存）**：三种方案的每卡显存与通信占比对比。
- **实测（选点运行）**：多 rank 代码路径的行为观察（分片占用、通信调用序列）。
- **校准（解释误差）**：新模型规模下切分结论的泛化检查（留出验证）。
- **决策（提交）**：切分决策记录（选中方案、理由、通信收益判定）。
